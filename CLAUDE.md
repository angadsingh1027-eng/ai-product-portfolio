# Angad Singh: AI PM Portfolio

A content-driven portfolio site that positions Angad Singh as a Senior/Principal IC AI PM (agentic workflows, LLM evals, enterprise platforms). Audience: hiring managers and business leaders who read it in short bites. Spec: `docs/BUILD_SPEC.md` (see its Amendments section). Decisions and their reasons: `docs/DECISIONS.md`. Also read `AGENTS.md`: it carries rules Lovable manages.

## Golden rules (never break these)

1. **Content-driven.** Never hardcode copy, metrics, names, dates or URLs in components. Everything user-facing comes from `/content`. To change text, edit a content file, not a component.
2. **No invented facts.** Every number and claim must exist in a content file. If something is missing, write `TODO:` in the content file; the loader hides any item containing one. Do not guess or round metrics.
3. **Client anonymity.** Never name the card issuer behind the Zeta contact-center work. Write "a card issuer". The employer Zeta may be named. For JPMorganChase the work may be described, but no real figure and no toolstack name appears (model names may). Withheld figures appear as masked values (X%, Y×, Z%) with no footnote, only on the JPMorganChase card, never in the Home impact strip or on the Recognition page (ADR-015).
4. **Nothing is gated.** There is no password, backend or private folder (ADR-014). Real confidential figures live only in the owner's shared resume and never enter this repo.
5. **Validate before merging.** `npm run content:validate` must pass (zod schemas in `src/lib/content-schema.ts`, allowed values in `content/taxonomy.json`). A bad content file must fail loudly, not render blank.

## Stack

TanStack Start (React 19, Vite, Nitro on Cloudflare, server-rendered) + TypeScript + Tailwind v4 + shadcn/ui, as generated by Lovable. Code lives in GitHub and is synced with Lovable on the `lovable-sync` branch. There is no backend.

Lovable manages: `vite.config.ts` (keep `@lovable.dev/vite-tanstack-config`; do not add plugins it already includes), `src/routeTree.gen.ts` and any file whose header says it is generated. Do not hand-edit them.

## Content format

- `content/site.json`: name, nav, page titles and descriptions, every UI string. `pages.home.slots` sets the home slots in order, each with a `min` and `max`; a slot with fewer items than its `min` hides itself.
- `content/taxonomy.json`: allowed values for status, build kind, depth, placement, highlight kind and tags.
- `content/work/<slug>.json`: one case. Fields: `slug`, `order`, `title` (60 characters), `tagline` (110), `company`, `year`, `role`, `domain`, `summary` (280), `status`, `depth` (`full` or `snapshot`), `placement` (`work` or `builds`), `featured`, `chips` (up to 3, 24 characters each), `brief` (up to 5 lines: Problem, Call, Role, Result, Lesson), `kpis`, `proof`, `tags`.
- `content/work/<slug>.md`: the body of a `full` case, with `## Context`, `## Users and pain points`, `## Solution`, `## What I owned`. A `snapshot` case has no body.
- A KPI has `label`, `value` (18 characters), `how`, and optional `scope`, `featured`, `featuredOrder` and `masked`. A masked KPI or chip carries no digits: its value is one letter and an optional unit.
- `content/journey.json`, `builds.json`, `recognition.json`: lists loaded by `src/lib/content.ts`. Recognition items have a `kind` (award, credential or quote) from the taxonomy. There is no Writing page.

## Commands

- `npm run dev` runs the site locally.
- `npm run content:validate` checks every content file against its schema and rules.
- `npm test` runs all tests, including a check that no gate code or wording returns.
- `npm run build` is the production build.

## Workflow

- Work on a feature branch and open a pull request into `lovable-sync`. Never push to `lovable-sync` directly. Never rewrite pushed history (no force-push, rebase, amend or squash of pushed commits): Lovable syncs this branch.
- Publishing is manual: merging does not publish. After merging, the owner clicks Publish in Lovable. Remind them at the end of every task that changes the site.
- Commit messages in the imperative, one change each.
- Slash commands: `/add-case`, `/update-content` (in `.claude/commands/`).

## Definition of done

Content validates, tests and `npm run build` pass, every page renders at 375px and 1280px, no console errors, per-route title and meta description are set, and no real JPMorganChase figure appears anywhere.
