# Angad Singh: AI PM Portfolio

A content-driven portfolio site that positions Angad Singh as a Senior/Principal IC AI PM (agentic workflows, LLM evals, enterprise platforms). Audience: hiring managers and business leaders who read it in short bites. Spec: `docs/BUILD_SPEC.md` (see its Amendments section). Decisions and their reasons: `docs/DECISIONS.md`. Also read `AGENTS.md`: it carries rules Lovable manages.

## Golden rules (never break these)

1. **Content-driven.** Never hardcode copy, metrics, names, dates or URLs in components. Everything user-facing comes from `/content` (public) or the gate backend (private). To change text, edit a content file, not a component.
2. **No invented facts.** Every number and claim must exist in a content file. If something is missing, write `TODO:` in the content file; the loader hides any item containing one. Do not guess or round metrics.
3. **Client anonymity.** Never name the card issuer behind the Zeta contact-center work. Write "a card issuer". The employer Zeta may be named. For JPMorganChase the public site shows only the role line. Its accomplishments are gated (`experience-jpmorgan`); add no JPMorgan case studies or projects, and no internal metrics or system names in any public file.
4. **Gated content never ships to the browser or this repo.** `content-private/` is gitignored here and versioned in its own private repo (ADR-009). Never commit it, never import it from `src/`, never paste its text into Lovable chat. Never put the password, its hash or the service-role key in client code.
5. **Validate before merging.** `npm run content:validate` must pass (zod schemas in `src/lib/content-schema.ts`). A bad content file must fail loudly, not render blank.

## Stack

TanStack Start (React 19, Vite, Nitro on Cloudflare, server-rendered) + TypeScript + Tailwind v4 + shadcn/ui, as generated by Lovable. Code lives in GitHub and is synced with Lovable on the `lovable-sync` branch. The gate backend is the owner's own Supabase project (not Lovable Cloud), managed with the Supabase CLI from a `supabase/` folder added in the backend phase.

Lovable manages: `vite.config.ts` (keep `@lovable.dev/vite-tanstack-config`; do not add plugins it already includes), `src/routeTree.gen.ts` and any file whose header says it is generated. Do not hand-edit them.

## Content format

- `content/site.json`: name, nav, page titles and descriptions, every UI string, gate messages.
- `content/work/<slug>.json` + `<slug>.md`: one case study. JSON holds slug, order, title, company, year, role, domain, summary, `brief` (up to 5 lines: Problem, Call, Role, Result, Lesson), `kpis`, `proof`, `tags`, `hasPrivateDepth`. The markdown holds `## Context`, `## Users and pain points`, `## Solution`, `## What I owned`.
- `content/journey.json`, `builds.json`, `writing.json`, `proof.json`: lists loaded by `src/lib/content.ts`. A journey entry with `gated: true` shows a Depth gate keyed by its `id`.

## Commands

- `npm run dev` runs the site locally.
- `npm run content:validate` checks every content file against its schema.
- `npm test` runs all tests.
- `npm run gate:mock` starts a local mock of the gate API on port 8787 (password `demo-password`). Copy `.env.example` to `.env.local` to point the site at it.
- `npm run build` is the production build.

## Workflow

- The site calls only `POST {VITE_GATE_API_URL}/verify-password` with `{ slug, password }` and reads `{ content }`. Nothing else about the backend may appear in `src/`.
- Work on a feature branch and open a pull request into `lovable-sync`. Never push to `lovable-sync` directly. Never rewrite pushed history (no force-push, rebase, amend or squash of pushed commits): Lovable syncs this branch.
- Publishing is manual: merging does not publish. After merging, the owner clicks Publish in Lovable. Remind them at the end of every task that changes the site.
- Commit messages in the imperative, one change each.
- Slash commands: `/add-case`, `/update-content` (in `.claude/commands/`).

## Definition of done

Content validates, tests and `npm run build` pass, every page renders at 375px and 1280px, no console errors, per-route title and meta description are set, and the gated sections show nothing without the password (check in a private window).
